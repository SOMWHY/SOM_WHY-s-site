---

上传 PDF 或 Markdown 文件后，系统会逐页解析并切分，同时保留页码归属；接着将文本块嵌入 pgvector，再基于这些段落回答问题，并通过单个连接流式传回答案和来源引用。

## 检索与问答

- 支持 PDF 和 Markdown 文档上传，包括拖放；单文件上限 4 MB，与 Vercel 请求体限制一致
- 按页解析 PDF，引用可以指向具体页码
- 按段落切分文本块（1800 字符，重叠 240 字符），并保留页码归属
- 将 1536 维向量批量写入 pgvector，通过 HNSW 索引按余弦相似度检索，并设置相似度阈值
- 答案以流式形式返回，来源作为消息元数据一同传输，无需额外请求
- 删除文档时会级联删除文本块和统计信息，且无法恢复

## 知识视图

- **结构化摘要**：提炼核心观点、关键数据、结论和标签，并使用 Zod schema 校验
- **思维导图**：模型生成扁平节点，前端绘制可折叠 SVG 主题树，支持缩放和平移
- **文本块浏览**：按页码列出每个文本块的原文，和聊天引用形成闭环

## 对话与访问控制

- 刷新后仍保留历史记录，可切换或删除多个会话
- 限定提问范围：输入 `@` 选择文档，检索只在所选文档内进行；无匹配结果时不会回退到整个知识库
- 仅支持 GitHub OAuth 登录；没有注册表单，也不使用密码。任何 GitHub 账户都可以登录
- 除 `/login` 外强制要求认证：页面返回 302，API 返回 401
- 文档、会话和消息按用户隔离；访问他人资源时返回 404，不泄露资源是否存在

## 技术栈

使用 Next.js 16 App Router、React 19 和 TypeScript，Tailwind CSS v4 与 `@tailwindcss/typography`，`ai@7`、`@ai-sdk/react` 和 `@ai-sdk/openai`，Neon Postgres、pgvector 与 Drizzle ORM，Zod 4，以及 `pdf-parse` v2 和 `mammoth`。项目部署在 Vercel，采用 MIT 协议。

## 已知限制

README 列出的限制包括：仅支持 GitHub OAuth；删除不可撤销，且过去会话中的引用不受影响；虽有 `.docx` 解析代码，上传界面只接受 PDF 和 Markdown；上传同步执行，大文档应改用后台任务和轮询；摘要与思维导图最多只使用前 24 个文本块作为上下文。
